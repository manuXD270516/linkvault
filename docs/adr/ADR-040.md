# ADR-040 — Filtro de rango salarial en búsqueda (Meili)

**Estado:** Accepted · **Fecha:** 2026-09-23 · **Change:** `search-salary-range`

**Origen:** B9r (`salaryCurrency`) + reflect critic/business. Relacionados: ADR-036 (search),
ADR-006 (Meili).

## Contexto

El preview ya guarda `salary.{min,max,currency,period}`. Solo `salaryCurrency` era filterable;
sin rango el usuario no acota banda salarial en `/buscar`.

## Decisión

1. **Index:** `job_preview` lleva `salaryMin` / `salaryMax` (números) cuando existen; omitidos
   o `null` al limpiar (Meili merge). Filterable en **api y worker**.
2. **Solape (query):**
   - `minSalary=M` → `(salaryMax >= M) OR (salaryMax IS NULL AND salaryMin >= M)`
   - `maxSalary=X` → `(salaryMin <= X) OR (salaryMin IS NULL AND salaryMax <= X)`
   - Docs sin ningún número: fuera si hay filtro de rango.
3. **Parse:** query string de dígitos enteros ≥ 0; vacío/ausente = no filtrar; sin
   `z.coerce.number()`; `min > max` → `400`.
4. **Period / salaryText:** fuera de alcance **en este ADR** (no normalizar unidades;
   no inferir números). Enmienda: **ADR-046** añade parse determinista de texto
   salarial → `salary.min`/`max` cuando ambos faltan.
5. **Plan:** fila 26 en `docs/design-v0.2.md` §6.

## Alternativas descartadas

- Filtrar solo cuando ambos min y max existen (excluye el caso LatAm más común).
- Normalizar todo a monthly (scope creep / datos incompletos).

## Consecuencias

- Backfill `job_preview` tras deploy de settings.
- SPA D3b trata rango como LatAm (`job_preview`).
- Fake Meili de tests debe evaluar comparaciones numéricas e `IS NULL`.
