# ADR-045 — Destino de guardado en discovery (grupo opcional)

**Estado:** Accepted · **Fecha:** 2026-09-23 · **Change:** `discovery-save-group-picker`

**Origen:** enmienda a ADR-043 (§guardar solo privado en v1). Relacionados: ADR-038
(extensión: mismo contrato `POST /api/links` + selector de grupo).

## Contexto

Discovery v1 guardaba solo en lista privada. El valor colaborativo del vault es el
grupo; sin picker, el inbound de `/descubrir` no entra al feed. La extensión ya
ofrece Privado (default) | grupo sobre el mismo endpoint.

## Decisión

1. **Destino a nivel de página** en `/descubrir`: Privado (default) o un grupo del
   que el usuario es miembro. Todos los CTA Guardar de la sesión usan ese destino.
2. **Default privado:** sin `groupId` salvo opt-in (B2 / coherencia con extensión).
3. **Sin API nueva:** solo `POST /api/links` con `{ url }` o `{ url, groupId }`.
4. **Carga de grupos fail-open:** fallo o lista vacía → solo Privado (+ aviso no
   bloqueante si falló la carga). Si el grupo seleccionado desaparece tras reload →
   reset a Privado.
5. **Captura al click:** el `groupId` (o su ausencia) se fija al inicio de `save`
   antes de `await`, para no mezclar destino mid-flight.
6. **Feedback:** `created` / `already` (`already_there`) / `error` (incl. `404
   group_not_found`).

## Alternativas descartadas

- Picker por hit; default = grupo; endpoint `discovery/save`; multi-grupo en un click.

## Consecuencias

- Plan §6 fila **31** `discovery-save-group-picker`.
- ADR-043 queda enmendado: el save desde discovery **puede** incluir `groupId`.
