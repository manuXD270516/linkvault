# ADR-046 — Parse determinista de texto salarial (enmienda ADR-040)

**Estado:** Accepted · **Fecha:** 2026-09-23 · **Change:** `search-salary-text-parse`

**Origen:** hueco de ADR-040 §4 (`salaryText` / inferir números fuera de alcance). Relacionados:
ADR-040 (filtro rango), ADR-010 (procedencia), ADR-009 (outbox / backfill-search).

## Contexto

El filtro `minSalary`/`maxSalary` solo ve extremos numéricos en Meili. Muchas vacantes
LatAm publican el sueldo solo en texto (JSON-LD `baseSalary` string, o anclas en
`summary`) y dejan `salary.min`/`max` null → hits invisibles al filtrar.

## Decisión

1. **Parser puro** `parseSalaryText` en `libs/shared`: determinista, sin I/O; `null` si
   no hay confianza (no inventar).
2. **Cuándo:** solo si **ambos** `salary.min` y `salary.max` son null/ausentes.
3. **No-op** si `previewSources.salary` es `manual` o `pasted`. Source tras parse:
   **`auto`** + extractor `parse-salary-text` (prohibido kind `derived`).
4. **Texto (prioridad live):** blob `baseSalary` textual de JSON-LD; si no, `summary`
   con anclas. Backfill offline: solo `summary`.
5. **Backfill two-step:** (1) CLI parse → Mongo `$set` (sin Meili); (2)
   `api:backfill-search --docType=job_preview` vía outbox. Sin dual-write Meili.
6. **Period:** se puede rellenar el campo; **no** normalizar montos entre hour/month/year
   en el filtro (sigue ADR-040).

## Alternativas descartadas

- LLM como extractor primario de salario.
- Completar un solo extremo cuando el otro ya existe (v1 estricto).
- Campo libre `salaryText` en el modelo.

## Consecuencias

- Enmienda ADR-040 §4: el parse de texto salarial **sí** está en alcance vía este ADR.
