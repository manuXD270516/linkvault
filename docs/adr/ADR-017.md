# ADR-017 — Andamiaje de plataforma: límites por lint, entorno local solo infraestructura, salud en dos niveles

**Estado:** Aceptado · **Fecha:** 2026-09-16 · **Origen:** debate critic/business/reflect del change `bootstrap-monorepo` (iteración 1)

## Contexto
El change `bootstrap-monorepo` convierte en verificables las reglas de CLAUDE.md y fija cómo se ejecuta el proyecto en
desarrollo y en CI. El debate detectó dos P0 (Critic C1, C2) y un V0 (Business B2) en el entorno local, y varias
decisiones que los changes siguientes heredarán.

## Decisión
1. **Límites en dos mecanismos que no se pisan.** `@nx/enforce-module-boundaries` con tags `scope:*`, `type:*` y
   `platform:node|browser|any` para dependencias entre proyectos, donde solo los archivos de test pueden importar
   proyectos `type:test-util`; `no-restricted-imports` por ruta para la capa de
   dominio y `@typescript-eslint/no-restricted-imports` para los SDKs de IA. Son reglas distintas a propósito: ESLint no
   combina las opciones de una misma regla entre overrides. Cada regla tiene una fila en un test tabular.
2. **El compose de desarrollo solo levanta infraestructura** (mongo, redis, minio; ollama bajo perfil `ai-local`). Las
   apps corren en el host con `nx serve`. Los Dockerfiles se difieren a `deploy-prod`.
3. **Replica set inicializado por el healthcheck de `mongo`**, idempotente, con el miembro anunciado como `mongo:27017`.
   Desde el host se conecta con `directConnection=true`. Se descarta el contenedor de init separado para no depender del
   comportamiento de `docker compose up --wait` con contenedores que terminan.
4. **Tests con `mongodb-memory-server`** en replica set de un nodo, versión exacta fijada, un replica set por proyecto.
   Se descartan servicios del runner (duplican la inicialización) y testcontainers (Docker obligatorio en cada corrida).
5. **Salud en dos niveles.** `GET /health/live` responde siempre 200 si el proceso vive; `GET /health` es readiness sobre
   Mongo y Redis con 500 ms por comprobación y 1500 ms en total. Ambas rutas quedan fuera del prefijo global `/api`.
6. **Conexiones perezosas y configuración validada al arrancar.** Las apps arrancan aunque Mongo o Redis no estén; una
   variable obligatoria ausente detiene el arranque con un mensaje que la nombra.

## Consecuencias
- `/lv:smoke` y el RUNBOOK funcionan sin cambios: compose para infraestructura y `nx serve` para las apps.
- `deploy-prod` hereda la tarea de crear imágenes endurecidas y el compose de producción con las apps.
- La restricción "`domain/` no importa otros módulos" queda pendiente hasta `auth-users`, primer change con dos módulos.
- CI y desarrollo comparten versión mayor de Mongo y topología de replica set, no el mismo proceso de Mongo.
