# ADR-038 — Sesiones de extensión Chromium (refresh en body + CORS)

**Estado:** Accepted · **Fecha:** 2026-09-23 · **Change:** `browser-extension`

**Origen:** design.md G5 / F3 `extension` + reflect critic/business del change. Relacionados:
ADR-012 (auth cookie SPA; enmienda abajo), ADR-020 (headers CSRF).

## Contexto

La SPA guarda el access en memoria y el refresh en cookie `httpOnly` `Path=/api/auth`. Una
extensión MV3 no comparte ese origen ni puede reutilizar la cookie. Hace falta un cliente
`extension` con el mismo rigor de rotación/reuso, sin ensanchar el login web para devolver
refresh en JSON al SPA.

## Decisión

1. **Campo `client`:** `'web' | 'extension'` en la familia de sesión. Legacy sin campo ≡ `web`.
2. **Rutas dedicadas:** `POST /api/auth/extension/login|refresh|logout`. Éxito y error **no**
   fijan ni borran `lv_refresh`. Refresh solo en body JSON; solo sesiones `client=extension`.
3. **Aislamiento:** refresh `extension` rechazado en `POST /api/auth/refresh` (cookie); refresh
   `web` rechazado en `extension/refresh`.
4. **CSRF + rate-limit:** mismas reglas que el resto de `POST /api/auth/*`
   (`X-Requested-With: linkvault`) y contadores compartidos con `POST /api/auth/login`.
5. **Rutas públicas:** `extension/login|refresh|logout` en la lista exhaustiva de
   `auth/sessions` (sin Bearer).
6. **CORS:** `EXTENSION_CORS_ORIGINS` (CSV de `chrome-extension://…`). Default vacío = off.
   Allowlist acota orígenes página/web; una extensión con `host_permissions` puede omitir CORS —
   la defensa real es auth + límites + `client` + no loguear tokens.
7. **Plan:** fila 24 en `docs/design-v0.2.md` §6.

## Enmienda a ADR-012

ADR-012 sigue vigente para el **cliente web** (access memoria + refresh cookie). El cliente
**extensión** usa refresh opaco en el cuerpo JSON y almacenamiento de la extensión
(`chrome.storage.local`), no cookie httpOnly. Misma familia de rotación/reuso/TTL; distinto
transporte.

## Alternativas descartadas

- Devolver `refreshToken` en el login web al SPA (aumenta superficie XSS).
- Device-code / PAT de larga duración (fase posterior).
- Reutilizar solo cookie con `Path=/` (rompe aislamiento SPA y Path estrecho).

## Consecuencias

- Módulo auth gana endpoints y campo `client`.
- API puede habilitar CORS allowlist.
- Nuevo app Nx `apps/extension` (MV3).
