# ADR-043 — Discovery de vacantes (APIs públicas)

**Estado:** Accepted · **Fecha:** 2026-09-23 · **Change:** `job-discovery`

**Origen:** design.md F3 + reflect critic/business. Relacionados: ADR-008 (dedupe),
ADR-022 (robots/enrichment; boards bloqueados fuera de discovery), ADR-020 (rate-limit).

## Contexto

El vault guarda links pegados; discovery permite **buscar** en bolsas lícitas y guardar
con un clic, sin scraping agresivo ni headless.

## Decisión

1. **Boards v1:** Get on Board (`GET https://www.getonbrd.com/api/v0/search/jobs`, API
   pública) y Remote OK (`GET https://remoteok.com/api` + cache Redis 15m + egress
   limiter + single-flight). Mock para CI (`DISCOVERY_CHAIN=mock`).
2. **Fuera:** LinkedIn, Indeed, Computrabajo, Trabajopolis como fuentes; headless.
3. **API:** `GET /api/discovery/search` autenticado; `page`/`pageSize` (cap ≤20/board);
   `degraded[]` con reason enum; flag off → `503`; RL usuario 30/min fail-open si Redis
   cae; egress Remote OK fail-closed.
4. **Guardar:** solo `POST /api/links` (privado v1); SPA feedback creado/ya existía/error.
5. **Platform:** añadir `remoteok` al schema + canonicalizer.
6. **Flag:** `FEATURE_DISCOVERY` default false.
7. **Plan:** fila **29** en `docs/design-v0.2.md` §6 (27 = `job-link-reopen`, 28 = `demo-seed`).

## Alternativas descartadas

- Scrapers HTML de boards robots-blocked.
- Endpoint discovery/save propio (dual path).
- Picker de grupo en v1.

## Consecuencias

- Módulo Nest `discovery` en api; SPA `/descubrir`.
- Atribución Remote OK en UI; UA identificable.
